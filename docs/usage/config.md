# 設定

Shionji の設定は 2 種類に分かれる。導入手順は [インストール手順](setup.md) を参照。

| 種類 | 内容 | 編集場所 |
| --- | --- | --- |
| 接続先設定 | ポートフォワード 1 本ぶんの定義 | 接続先設定ウィンドウ |
| アプリ設定 | アプリ全体の挙動 | 設定ウィンドウ、または設定ファイルの直接編集 |

## 用語

| 用語 | 意味 |
| --- | --- |
| 接続先設定 | ポートフォワード 1 本ぶんの定義。名前を付けて保存し、一覧から接続する |
| 転送先 | 最終的に到達したい相手。エンドポイントやホストと、そのポート |
| 経路 | 転送先へ届くために SSM セッションを張る相手。踏み台とも呼ぶ。転送先自身に SSM セッションを張れる場合は「直接」を選ぶ |
| リソース自動検索 | 転送先や経路を、固定のホスト名やインスタンス ID ではなく検索条件で指定する仕組み。接続のたびに条件に一致する実リソースを AWS へ問い合わせて特定するため、入れ替わるリソースを追いかけられる |
| 複数一致 | リソース自動検索の条件に 2 件以上のリソースが該当した状態。どれに繋ぐべきか決められないため、既定では接続せずに候補を一覧表示する |

## 接続先設定

### 基本

| 項目 | 内容 |
| --- | --- |
| 設定名 | 一覧とログに出る名前 |
| AWS プロファイル | `~/.aws/config` のプロファイル名 |
| リージョン | 接続先が属するリージョン |
| ローカルポート | 待ち受けるローカル側のポート番号。空にすると接続時に空きポートを自動で割り当てる |

### 転送先

種別によって入力する項目が変わる。

| 種別 | 指定する内容 |
| --- | --- |
| エンドポイント / IP 直接指定 | 転送先ホストと転送先ポート |
| ElastiCache (検索) | 検索条件、エンドポイント (Primary / Reader / Configuration)、転送先ポート |
| Aurora (検索) | 検索条件、エンドポイント (Writer / Reader)、転送先ポート |
| EC2 インスタンス (検索) | 検索条件、転送先ポート |
| ECS タスク (検索) | クラスター、サービス、コンテナ、転送先ポート |

ElastiCache と Aurora は転送先ポートを空にするとリソースの既定ポートを使う。EC2 と ECS は既定ポートを持たないため、転送先ポートの指定が必須。

### 検索条件

ElastiCache / Aurora / EC2 のリソース自動検索では、名前パターンとタグ条件で絞り込む。

| 項目 | 内容 |
| --- | --- |
| 名前パターン | glob で書く。`*` は 0 文字以上の任意の並び、`?` は任意の 1 文字に一致する。大文字と小文字は区別しない。空にすると名前では絞らない |
| タグ条件 | キーと値の組を行として並べる。並べた条件はすべて満たすものだけが該当する (AND)。値は完全一致で、大文字と小文字を区別する |
| 複数一致時は先頭を採用 | 有効にすると、複数一致でもエラーにせず先頭の 1 件へ接続する。無効の場合は候補を一覧表示して接続しない |

ECS タスクの検索はクラスターとサービスとコンテナで絞る。名前パターンとタグ条件は使わない。

### 経路

| 種別 | 指定する内容 |
| --- | --- |
| 直接 (転送先に SSM セッション) | なし |
| EC2 踏み台 (インスタンス ID) | インスタンス ID |
| EC2 踏み台 (検索) | 名前パターン、タグ条件、複数一致時の扱い |
| ECS 踏み台 (ECS Exec) | クラスター、サービス、コンテナ |

転送先と経路の組み合わせには制約がある。

| 転送先 | 直接 | EC2 / ECS 踏み台 |
| --- | --- | --- |
| エンドポイント / IP 直接指定 | 指定できない | 使える |
| ElastiCache / Aurora | 指定できない | 使える |
| EC2 / ECS | 使える | 使える |

エンドポイント直接指定と ElastiCache / Aurora は SSM セッションを張る相手にならないため、踏み台が要る。保存時にこの検証が行われ、満たさない組み合わせは理由とともに拒否される。

### オプション

| 項目 | 内容 |
| --- | --- |
| 予期せぬ切断時に自動再接続する | 確立後に意図せず切断された場合に再接続を試みる。間隔は 2 秒から 30 秒へ段階的に延び、5 回で打ち切る |
| アプリ起動時に自動接続する | アプリの起動時にこの接続先へ自動で接続する |

## アプリ設定

### 設定ウィンドウで変えるもの

メニューバーの「ツール」から開く。大項目ごとに分かれている。

| 大項目 | 項目 | 内容 |
| --- | --- | --- |
| 表示 | カラーテーマ | システムに従う / ライト / ダーク。選ぶとその場で反映される |
| ログ | ログファイルの保存先 | 空にすると既定に戻る |
| 設定 | 接続先設定ファイルの保存先 | 空にすると既定に戻る |

保存先を変えると、その場で既存のファイルが新しい場所へ移される。移動先に同名のファイルがある場合は上書きせず、その旨を画面に出す。アプリが新しい場所を見るのは次回起動からで、保存すると再起動を促すメッセージが出る。

### 設定ファイルを直接編集して変えるもの

画面に無い項目は `%APPDATA%\Shionji\appsettings.json` を直接編集する。アプリの終了中に編集し、次回起動で反映される。

| キー | 型 | 既定 | 内容 |
| --- | --- | --- | --- |
| `PluginPath` | 文字列 | なし | `session-manager-plugin.exe` の場所。指定しない場合は既定の導入先と `PATH` から探す |
| `AwsEndpointOverride` | 文字列 | なし | AWS API の宛先の上書き。VPC エンドポイント経由にする場合などに使う |
| `MinimizeToTray` | 真偽値 | `true` | ウィンドウを閉じたときにタスクトレイへ格納するか。`false` にすると終了する |
| `LogRetentionDays` | 数値 | `30` | ログファイルを保持する日数。これを過ぎたファイルは起動時に削除される |
| `Theme` | 文字列 | `System` | カラーテーマ。設定ウィンドウと同じもの |
| `LogDirectory` | 文字列 | なし | ログの保存先。設定ウィンドウと同じもの |
| `ConfigsDirectory` | 文字列 | なし | 接続先設定の保存先。設定ウィンドウと同じもの |

読み込めない内容が書かれていた場合は、その項目を既定値として起動する。設定ファイルの不備でアプリが起動できなくなることはない。

## 保存先

| ファイル | 既定の場所 | 移動 |
| --- | --- | --- |
| アプリ設定 `appsettings.json` | `%APPDATA%\Shionji\` | できない |
| 接続先設定 `configs.json` | `%APPDATA%\Shionji\` | できる |
| ログ `shionji-yyyyMMdd.log` | `%APPDATA%\Shionji\logs\` | できる |

アプリ設定ファイルだけは場所を変えられない。他の 2 つの保存先の指定がこのファイルに入っているため、これ自体を動かすと次回起動で見つけられなくなる。

接続先設定ファイルが壊れて読めない場合、そのファイルは `.corrupt-yyyyMMddHHmmss` を付けて退避され、空の一覧で起動する。手で編集した内容を失わずに原因を調べられる。

デモモード (`--demo` 付きで起動) はどのファイルにも書き込まない。設定もログもメモリ上だけで扱う。

## ログ

1 つの出来事につき短い要約と詳細フィールドを持ち、画面には要約だけ、ファイルには詳細まで出力する。ステータスバーは一目で状況が分かる簡潔さを保ち、ファイルは監査に必要な事実を残す。

画面のステータスバーと、その「ログ」ボタンから開く履歴に出るのは要約だけ。

```
[設定名: api-db] localhost:13306 で接続しました
```

ファイルは `ISO 8601 タイムスタンプ(オフセット付き) [レベル] カテゴリ: 要約 | key=値 …` の書式で、要約に詳細フィールドが続く。

```
2026-08-08T18:13:56.615+09:00 [INF] Shionji.Application.TunnelSupervisor: [設定名: api-db] localhost:13306 で接続しました | 試行=6128f3e6 設定=api-db 転送先=demo-aurora.cluster-demo.ap-northeast-1.rds.amazonaws.com:3306 経路=EC2:i-0demo0123456789a SSMターゲット=i-0demo0123456789a 文書=AWS-StartPortForwardingSessionToRemoteHost プロファイル=demo@ap-northeast-1 ローカル=localhost:13306 セッション=s-demo508478
```

値に空白が含まれる場合は `"` で囲まれるため、`key=値` として機械的に読み取れる。

記録される項目を次に示す。

| 項目 | 内容 |
| --- | --- |
| 起動時の 1 行 | アプリの版、OS 利用者 (`ドメイン\ユーザー`)、端末名、プロセス ID |
| `試行` | 接続試行ごとの相関 ID。1 回の試行に属する行を突き合わせる。再接続では振り直す |
| `転送先` | 実際に繋いだエンドポイントとポート |
| `経路` | 経由した踏み台 |
| `SSMターゲット` | SSM セッションを張った相手の識別子 |
| `文書` | 使用した SSM ドキュメント名 |
| `プロファイル` | 使用した AWS プロファイルとリージョン |
| `セッション` | SSM セッション ID。CloudTrail や `aws ssm describe-sessions` と突き合わせる鍵 |
| 自動検索の証跡 | 検索条件がどの実リソースに特定されたか。表示名、ARN またはインスタンス ID、エンドポイント |
| 切断の記録 | 理由 (利用者操作 / 設定変更 / アプリ終了 / 予期せぬ終了)、接続していた時間、原因のフェーズとコード |

セッショントークンと資格情報はログに出力しない。
